# 提炼管线（Distillation Pipeline）——把真实规则"喂"进 skill 的标准流程

> 这是本 skill 的"自我进化入口"。当用户提供**一份真实可执行的规则**（无论偏门/高级/能跑），或要求分析一个新源时，按这个管线把它的可复用范式沉淀进知识库——让它从"一次性作品"变成"能力"。

## 为什么要有这张流程

`legadoSkill` 之所以能持续变强，核心是它维护了一个**真实书源案例库 + 三阶段工作流 + 自我进化机制**：每吸收一份真实规则，就提炼出高频选择器、结构形态、特殊处理范式，再固化为规范与口诀。本 skill 照搬这套：**真实规则 → 结构化剖析 → 通用范式 → 固化进正文/速查**。

## 提炼五步

### 第 1 步：通读并定位规则"现在就能用/值得沉淀"的点

先解包/通读整份 `rule.json`（含 `pages[]`、`libs.zip`、`data.zip`）。用"写源五维度"通读：首页/搜索/详情/选集播放/子页面。标记它**异于常规**、**别人抄不来**的部分。

### 第 2 步：跳出站点，抽象出"范式"

把每位注意到的写法翻译成**可迁移到任意站点**的范式，自问三连：
- 这个能力还依赖当前站点的哪个私有东西？（域名/密钥/登录态/成人内容 → 剔除）
- 换一个别的站点/别的解析对象（影视↔漫画↔阅读↔音频），这套还能通用吗？
- 能缩成一句"骨架写法"或"口诀"吗？

### 第 3 步：按难度决定沉淀层级

| 范式的通用性 | 沉淀到哪里 |
| --- | --- |
| 极通用、几乎每源都用（分流顺序、详情头） | 提升进 `SKILL.md` 正文（`编写规范`/`禁区与口诀`/`播放分流`） |
| 高通用、只在"高级源"（聚合/网盘/信息型）用 | 进 `references/examples/advanced-source-template.md`（骨架占位符） |
| 中等、某一类源的完整做法 | 单独写一份剖析文档（如 `references/examples/qingdou-architecture.md`），按"写源范式"组织 |
| 个别站点专属 | 不沉淀，仅在交付说明里提一句 |

### 第 4 步：创作剖析文档（标准模板）

若需要新建剖析文档，用固定结构，便于后续检索：
```
# 《{规则名}》架构剖析与写源范式速查
## 0. 整体架构（怎么读这个大源）
## 1. {范式A}（命名清晰，写源时要用到）
## 2. {范式B}
...
## 一句话总结迁移清单   ← 结尾必带：写新源时从本文取哪些骨架
```

写范式时**给完整代码段 + 一句"要点"**（为什么这么写），因为 AI 写源时要能照抄，不是看概念。

### 第 5 步：回写正文 + 登记参考文件

- 若提炼出新的通用范式/口诀，追加进 `SKILL.md` 的对应章节（`编写规范`/`禁区与口诀`/`高阶源能力`）。
- 把新文件登记进 `SKILL.md` 的「参考文件」清单。
- 更新版本号（`version` 递增），并重新打包 `.hk小程序.zip`。

## 吸收知识时的人格要求

- **禁止臆造**：提炼的每条范式都要能在提供的真实规则里找到对应代码/字段，标注来源。抓不到的就说抓不到，不脑补。
- **只提炼通用工程范式**，不复制具体站点、私有密钥、登录态、成人站点内容（这是 skill 能安全分发的底线）。
- 写剖析文档时按"写源时要用的范式"组织，而非"按页面流水账"。

## 与"批量喂规则"的配合（用户给出大量规则时）

当用户一次性提供数百上千个规则备份时，**不要幻想一股脑全吸收**。做法：
1. 先做"类型画像"：扫描文件名/结构，按 视频聚合/单影视/漫画/音频/阅读/网盘/自定义规则 分类，统计各自的占比与共性。
2. 挑**代表性样本**（每类 2–5 个，优先选"能用/高级/结构完整"的）：跑第 1–5 步做深提炼。
3. 对海量同类规则只做"模式比对"：验证已提炼范式覆盖面，抓"新写法/异常写法"再深挖，普通写法则跳过。
4. 产出物 = 每类一份剖析/范式速查 + 提炼报告（覆盖了哪些类型、吸收了什么范式、还缺什么）。

> 目标不是"存规则"，而是"把规则里的可复用规律变成 skill 的能力"。规则本体让用户自留，skill 只带走范式。
